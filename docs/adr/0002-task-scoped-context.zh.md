# ADR-0002：以任务级上下文替代全局 spec 准入

状态：已接受——维护者在本次文档迁移中明确要求。

## 决策

根指导按需指向工程规则、领域术语、相关 ADR 和一份经用户确认的任务/迭代上下文。
源码、测试、schema 和 manifest 描述当前事实；用户目标与可观察验收描述预期变化。
实质冲突与用户澄清后，记入对应的维护位置。新工作不再要求修订全局 spec、登记 Phase
或执行 `opi-implement plan`。

这取代旧 `docs/opi-spec*` 中 `AUTH-003`/`AUTH-004` 的权威链与 Phase 推导规则。
从工作区删除退役规范及 `docs/CONTEXT.md`，已提交版本由 Git 保留。
当前指导只描述当前实践，不保留退役提示。此次迁移不改写已有台账、快照及其哈希。
取消路线图约束不代表放松现有运行时安全或验证要求。

## 理由

实现和上游迭代很快，全局文字清单的同步成本过高。把同一份清单拆进多个必读文档，
只会复现问题。这里改为分离术语、决策、事实与临时范围，按条件加载，并随所属变更维护。

跨会话工作仍可使用功能级 spec。Matt 的 wayfinder 是可选的决策地图，不是每个功能的必经仪式。
项目适配将持久本地产物存放在 `docs/iterations/`，`.scratch/` 只放临时材料。
工程、术语和上下文文件只维护英文主本；已有双语文档继续同步。

## 影响

- 行为或决定变化时，更新或裁剪对应当前文档；终态迭代简报不再充当当前范围。
- 旧 Phase 工具仅用于明确选择的旧流程，受 [迁移边界](../../.agents/skills/_shared/references/legacy-phase-workflows.md) 约束。
  缺失旧输入仍是该流程的显式阻塞，但不是新工作的阻塞。后续工具迁移单独决策。
- 检查器验证当前文档结构、链接和产品契约，不要求已删除文档或退役提示继续存在。
- 此次不实现产品功能、不改变运行时契约、不迁移已有任务，也不授权 Git 发布。
  Matt 路径适配不是自动兼容性证明，仍需在一次真实、明确请求的迭代中验证。
