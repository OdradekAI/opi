## Dimensions

### 1. Provider abstraction, collection/Models, registry, factory, dispatch
**opi:** opi-ai defines a streaming-only `Provider` trait with a per-provider `ModelInfo` catalog, layered by a `ProviderRegistry` (spec resolution + model overrides) and a `ProviderCollection` facade (auth descriptors, compat metadata, stream/complete dispatch). `provider_factory.rs` is the single central construction site. Nine built-in providers; OpenAI-compatible custom profiles via TOML; extension-supplied providers via opi-agent. Key facts:
- `Provider` trait has `id`/`models`/`stream` only — `crates/opi-ai/src/provider.rs:12-23`
- `ModelInfo` carries 7 fields (no cost, headers, or thinking-level map) — `provider.rs:64-73`
- `ProviderRegistry` resolves `'provider:model'` string specs — `crates/opi-ai/src/registry.rs:117-293, 302-314`
- Single centralized factory across 9 ids — `crates/opi-coding-agent/src/provider_factory.rs:620-862, 236-246`
- 9-variant `ProviderError` to `ProviderErrorCategory` — `crates/opi-ai/src/provider.rs:124-218`
- `AuthDescriptor` is `#[non_exhaustive]` with only StaticApiKey/EnvApiKey/Resolved — `crates/opi-ai/src/provider_collection.rs:97-119`

**pi 0.80.2:** pi-ai defines a `Provider<TApi>` interface (id/auth/getModels/optional refreshModels/stream/streamSimple) and a `Models` collection with auth resolution, stream/complete/streamSimple/completeSimple dispatch. `createProvider()` is the universal factory; `builtinModels()` registers ~35 built-in providers. Auth is a full contract: per-provider ApiKeyAuth + OAuthAuth, a `CredentialStore`, env/ambient/OAuth resolution. Models carry cost, thinking-level maps, per-model compat/headers. A separate `ImagesModels` surface exists for image generation. Key facts:
- `Provider<TApi>` generic interface — `packages/ai/src/models.ts:32-72`
- `Model` carries 13+ fields incl. cost{4}, thinkingLevelMap, headers, compat — `packages/ai/src/types.ts:660-690`

- `ApiKeyAuth` + `OAuthAuth` + `CredentialStore{read/modify/delete}` — `packages/ai/src/auth/types.ts:47-69, 129-182`
- `ImagesModels` + `generateImages` — `packages/ai/src/images-models.ts:12-87`

### 4. Stream/transport lifecycle
**opi:** Uniform `AssistantStreamEvent` protocol and per-provider reqwest streaming with a `CancellationToken`. Retry/backoff lives in the opi-agent `agent_loop` (not the provider) with a manual exponential loop that honors cancel during sleep and suppresses retry once any stream content was delivered. Proxy is `reqwest::Proxy` at the HttpClient layer. Cache-control is minimal. Key facts:
- 12-variant `AssistantStreamEvent` — `crates/opi-ai/src/stream.rs:210-279`
- Agent-level retry with `RetryConfig`, suppressed after partial output — `crates/opi-agent/src/agent_loop.rs:86-87, 125, 396-451`
- `parse_retry_after` (seconds + IMF-fixdate + x-ratelimit-reset) — `crates/opi-ai/src/retry.rs:59-90`
- Cancellation via `CancellationToken` in stream + sleep — `agent_loop.rs:128-140, 436-450`
- `reqwest::Proxy::all` single global proxy; env HTTPS_PROXY wins — `crates/opi-ai/src/http.rs:122-153, 166-219`
- `CumulativeUsage` aggregator — `stream.rs:89-172`
- No cache_control markers emitted; no session-affinity headers — grep returns no matches

Cache-control is rich (Anthropic `cache_control` markers + 1h ttl, OpenAI `prompt_cache_key` + retention, session-affinity headers). Usage includes `cacheWrite1h` split and inline cost. Key facts:
