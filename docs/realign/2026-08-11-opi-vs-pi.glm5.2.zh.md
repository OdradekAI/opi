## 6. 会话模型

**opi:** opi 使用单一 JSONL 会话格式，版本 1，以 id/parent_id 条目构成扁平的仅追加树，加上由最后一条 `Leaf` 条目追踪的单个 active branch；SessionWriter/SessionReader 是具体 struct（无 storage trait）。该模型明确以 pi 的 legacy coding-agent v3 形态为蓝本（而非较新的 agent-core v4 抽象），并省略了 lanes、operation records、retainedTail compaction 与 SQL backends。重建从 active tip 沿 parent_id 回溯；崩溃恢复是三类划分（truncated/corrupt/unknown）；无迁移路径。

## 14. 权限与沙箱

**opi:** opi 叠加了三个独立的权限边界：一个核心工具策略门控（`is_mutating_tool` = write/edit/bash），在非交互/RPC 模式下除非设置 `--allow-mutating` 否则 fail-closed；文件工具的 workspace-root 路径限制（write/edit/ls/find/glob 使用 `WorkspaceOnly`，交互式 read 使用 `AllowOutsideWorkspace`）；以及项目信任（`trust.json`），门控 `.opi` 资源、AGENTS.md 和 CLAUDE.md 的加载。OS 级原生限制（Landlock+seccomp/Seatbelt/Job-Object）位于独立的 `opi-sandbox` crate 中，未链接进 `opi` 二进制，仅可作为可安装的 execution adapter 访问，由用户拥有的 Allow/Deny/Ask 能力权限映射治理。execution adapter 是 fail-closed 的（外部失败从不回退到本地；headless Ask 被拒绝）。遗留的 `[sandbox]`/`--sandbox`/`--sandbox-require` 面被显式拒绝。

## 18. Wire protocols and embedding

**opi:** opi 暴露三条独立的 LF 分隔 JSON（JSONL）wire，各自带自己的单向数字 schema 版本常量在 header 中通告：NDJSON_SCHEMA_VERSION=2（`--json` 非交互输出）、SDK_SCHEMA_VERSION=3（RPC/嵌入命令模型）和 TRACE_SCHEMA_VERSION=1（本地脱敏 trace envelope）。嵌入是库级（opi-agent 中的 Agent/SdkCommand/SdkResponse/StreamingProxy）加一个单会话 stdin/stdout RPC runner；一个独立的 opi-protocol crate 拥有用于 host<->backend 沙箱执行的冻结 command-execution-jsonl-v1 wire，而非嵌入。不存在 client/server 进程分离、版本协商握手、二进制帧封装或 browser/web 目标。
