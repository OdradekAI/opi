## Layer A — current contracts and differences

### A.1 Verdict overview (what the numbers mean)

- **equivalent (38):** deep-fidelity ports concentrated in pi-ai internals — pricing
  math, thinking levels/clamping, provider registry ids, OAuth flows (9 providers,
  all client ids/ports/endpoints match; sole drift: ChatGPT agent-name hint
  `"opi"` vs `"Pi"`), credential-store contract, refresh-under-lock, ADC/AWS-chain/
  federation source sets, WS codex transport, anthropic server-side fallback,
  image-generation and 4 classifier contracts, `repairJson`, streaming-JSON
  cascade, uuidv7, shortHash, overflow predicates, UTF-8 chunk decoder,
  transcript replay core, `string_enum`, skills loader, no-eval schema property,
  telemetry no-exporter posture.
- **partial (72):** capability present with reduced/different parameters — most of
  the agent loop (queues, tool continuation, cancellation, state updates, thinking),
  CLI flags with narrower semantics, settings, trust, compaction, session fork,
  read/write/ops seams, ModelInfo fields, models-store, remote catalog (see A.3).
- **different (77):** both implement, observably divergent — event wire shapes,
  error seams, session formats, tool schemas, edit model, system-prompt structure,
  JSON/RPC streams, TUI engine, schema engine, telemetry contract, eval toolkit.
- **missing (87):** bounded-absence-verified gaps — the largest clusters are
  **MCP (entire stack), codemode sandbox, TUI engine subsystems, extension API
  surface, chord/durable runtime, client identity, remote-catalog refresh semantics,
  nested tool calls, output guard, cache warming, HTML export, auth subcommands,
  self-update, migrations, virtual models, tool-search, llama.cpp provider**.
- **opi-only (18):** authority/evidence substrate, event redaction, SDK JSONL
  protocol, durable session stack (transcript-class), diagnostics sinks, execution
  backend router + sandbox adapters, doctor, package trust/enable, opi-eval
  machinery, per-run evidence manifests, OS-level restriction, opi TUI widgets.
- **unresolved (2):** catalog-revision content parity (offline), per-provider model
  counts (pi generated data absent from export).

### A.2 Caller-flow trace (product heart: agent session)

```text
pi:      pi(cli.ts) -> modes -> AgentSession(core/agent-session.ts) -> Agent(agent.ts)
         -> runAgentLoop: prepareNextTurn -> prepareRequest(every turn) -> streamFn
         -> partials as message events -> executeToolCalls(before/after hooks,
         onUpdate progress, nested runToolCall) -> finishTurn(force-continue option)
         -> steering/follow-up polls(QueueMode) -> failure = append failure message
         -> session-manager v3 JSONL (lazy create, per-cwd dirs)

opi:     opi(cli.rs) -> runner/interactive/rpc -> harness.rs -> Agent::new(registry
         + authorizer) -> arm_run -> agent_loop: steering drain(all) ->
         prepare_initial_turn(first turn only) -> Models::prepare_call ->
         ChatStream events(assistant-only message events, redacted deltas) ->
         preflight(resolve -> before-hook -> schema -> authorize) ->
         execute_authorized(no progress wiring) -> ToolExecutionEnd(source order)
         -> should_stop_after_turn(bool; cannot force a turn) -> queue poll ->
         prepare_next_turn_transaction(warranted) -> failure = rollback to
         committed baseline -> SessionCoordinator v2 JSONL (eager create, flat dir)
```

### A.3 Highest-impact differences (records cited; full detail in evidence files)

**Model/runtime layer (Dims 1,3,4):**
- Catalog data: opi bundles a byte-verified pi-published artifact but pinned to the
  **pi-ai 1.3.0 revision** (`manifest.json` `local_origin: .repo/pi-1.3.0`) while
  pi 1.5.0 pins `f4dbabe…` (AI-MOD-07); spot checks show 1.5.0-era entries present,
  full delta unprovable offline (AI-MOD-02). Product `--list-models` surfaces only
  **11** of the catalog's 42 providers (`provider_factory.rs:517`; EXT-16).
- `promptCache {short,long}` lifetimes exist in the artifact but are **dropped at
  decode** (two boolean substitutes; AI-MOD-03). No pi.dev overlay semantics:
  no ETag/304 revalidation, no 4 h window, no lastModified>generatedAt gate — opi's
  HTTP source is a plain GET; stored etag never drives a decision (AI-MOD-10).
  Radius gateway dynamic fetch absent (AI-MOD-11). pi refresh is concurrent +
  per-provider publication + unknown-type filtering; opi sequential, single
  end-commit, fail-closed (AI-MOD-09).
- Chat retry set narrower: pi retries 408/**409**/429/5xx + `x-should-retry`; opi
  chat admission retries only typed 429/408/504 (ProviderSide non-retryable), while
  opi's typed-op transports do reproduce the full ladder (AI-STR-06). Agent-level
  message-pattern classifier absent (quota/billing/gateway strings; AI-STR-07;
  AI-UTL-26 pattern drift incl. missing boundary lookarounds).
- No default 10-minute request timeout (pi SDK default) — opi hangs until cancelled
  unless caller sets `timeout` (AI-STR-09). `durationMs` only on 3 of ~8 wires
  (AI-STR-04). Event wire tags differ (`toolcall_*`→`tool_call_*`, `toolUse`→
  `tool_use`) wherever events are serialized (AI-STR-01). Error seam: pi in-band
  `error` event vs opi single `Err(CallFailure)` (AI-STR-02); `partial` shared-live
  vs event-time clone (AI-STR-03). No ClientIdentity/UA/attribution framework;
  OpenRouter headers hardcoded to opi's own identity (AI-STR-19, AI-UTL-20,
  AGT-IDENT-01).
- Message data contract: canonical `ToolCall.arguments` is **raw text** in opi
  (pi: parsed object), no `namespace`, no `endTurn`, no tool-result
  `usage/durationMs/nestedCalls`; opi adds `not_executed`, `truncated`, `wire`,
  projection facts; Usage carries no embedded cost object (AI-UTL-08..12).

**Agent loop (Dim 5) — AGT batch:** `continue()` semantics differ (opi appends a
user message; pi continues context-only with tail-role validation, AGT-AGENT-03);

set immutable per Agent (pi swaps `state.tools` with announcement system messages,
AGT-STATE-03); no `reset()` (AGT-STATE-04); retry is loop-visible with events
(pi: invisible inside stream; AGT-RETRY-01).

**Tools/execution (Dims 8,14) — RUN batch:** pi tool set has `powershell`, opi has

## Layer B — conditional reproduction and engineering advice

Cards are engineering judgments traceable to A/H IDs; none is an authorized task.
"Acceptance" items define what would count as reproduction evidence (snapshot-
derived, executable). Ordering below is by dependency/risk-reduction, not product
priority.

### B-1 Refresh the pi-1.3.0→1.5.0 drift inside opi-ai (foundation for most parity work)

- **Findings:** AI-UTL-04 (tool-anchor 3-mode `resolveTranscriptTools` vs 2-way),
  AI-UTL-26/AI-STR-06..07 (retry pattern lists, status-boundary lookarounds, 409/5xx
  chat retry admission), AI-MOD-03 (`promptCache` decode), AI-MOD-07 (catalog pin),
  AI-STR-04 (`durationMs` on all wires), AGT-* pin comments (`.repo/pi-1.3.0`).
- **Approach:** re-pin ports against this snapshot: add `changes` transport mode +
  last-non-additive-change fold anchor; port the full retryable/non-retryable
  pattern lists + lookarounds into the classifier and widen chat admission to the
  typed-op ladder; decode `promptCache` into a typed field (keep booleans as
  projections); assign `duration_ms` in the remaining adapters or centrally in
  `ChatStream`; refresh the bundled catalog artifact to the 1.5.0 revision when
  network is allowed (verify with `scripts/pi-catalog/pack.py`).
- **Acceptance:** differential fixtures from pi's own tests
  (`transcript-tool-changes.test.ts:337-352`, `retry.test.ts`,
  `overflow.test.ts`) replayed against opi public APIs; negative controls: a
  removal+late-addition history, a "500"-containing id, a `409` chat response.
  Gates: Behavior+Verification. Test impact: `update`.
- **Trade-offs:** none of these change opi architecture; they are fidelity edits
  inside existing seams.

### B-2 Client identity / attribution framework

- **Findings:** AI-STR-19, AI-UTL-20, AGT-IDENT-01, EXT-24 (no UA modes, no
  OpenRouter/NVIDIA/OpenCode headers, hardcoded opi OpenRouter identity, no
  `PI_OAUTH_CALLBACK_HOST` runtime honor).
- **Approach:** add a `ClientIdentity` (UA mode + attribution map) on
  `Request`/`Models` config with field-by-field merge under user headers; replace
  the hardcoded OpenRouter headers with the attribution source (default opi's own);
  honor the callback-host env at runtime.
- **Acceptance:** request-capture fixtures proving identical header sets for the
  same identity config on both stacks; negative control: user-supplied header
  must override attribution. Gates: Behavior (wire-level), Safety (no secret in
  UA). Test impact: `add`.

### B-3 Remote catalog refresh semantics (if pi.dev parity is wanted)

- **Findings:** AI-MOD-10 (no ETag/304/window/freshness gate), AI-MOD-09
  (sequential/single-commit vs concurrent/per-provider), EXT-16 (no product
  registration of any source; 11-provider listing).
- **Approach:** implement conditional GET + `If-None-Match` + 304-persist +
  `lastModified > generatedAt` overlay gate in a product-owned source adapter
  (the SDK's `DynamicCatalogSource` seam already exists and deliberately owns no
  policy — keep it that way); register it in `provider_factory`; decide provider
  publication granularity (per-provider commit is pi behavior; opi's single commit
  is crash-safer — if kept, record as an intentional difference).
- **Acceptance:** local HTTP peer replaying 200/304/404/older-body schedules with
  identical store outcomes to pi's `withRemoteCatalog` tests; negative control: an
  older-than-bundled remote catalog must not apply. Gates: Behavior, Verification.
  Test impact: `add`.
- **Uncertainty:** pi.dev endpoint semantics observed from source only (offline).

### B-4 MCP client + product integration (largest single capability gap)

- **Findings:** MCP-01..05, EXT-09, EXT-25, CLI-06/10 (`--no-mcp`, `pi mcp`).
- **Approach:** standalone MCP client crate (opi already has building blocks:
  owned WS stack in opi-ai is provider-specific; JSONL child-process patterns in
  adapter_protocol) implementing initialize/initialized handshake, 2025-11-25
  negotiation set, stdio + Streamable-HTTP transports with session id/GET stream/
  Last-Event-ID resume, cancellation, progress-timeout renewal, OAuth subset
  (discovery/DCR/PKCE/refresh) — then product wiring: `mcp.json` discovery
  (user + trust-gated project), `mcp__<server>__<tool>` naming with 64-char
  sanitization, exposures, `/mcp` UI and `mcp` subcommand. Given opi's
  out-of-process extension stance, MCP servers already are processes — a native
  client does not compromise the isolation model.
- **Acceptance:** pi's own `packages/mcp/test/*` scenarios re-implemented against
  a local in-memory/stdio peer (connect, paginate, cancel, 401-recovery, resume);
  product: a configured server's tools appear, are trust-gated, and route through
  the full preflight pipeline; negative controls: cursor-dup rejection, expired-
  session error, unauthorized server blocked before spawn. Gates: all six.
  Test impact: `add` (large).
- **Dependencies:** B-1 not required; schema admission (SCM-TOOLVAL-10) already
  supports object-schema enforcement.

### B-5 Nested tool calls + codemode sandbox (joint card)

- **Findings:** AGT-TOOL-05, RUN-NEST-01, CDM-01..06, EXT-11/12, DUR-12.
- **Approach:** first add the agent-seam `run_tool_call` re-entry (hooks +
  validation + authorization applied, `parent_tool_call_id` on events, bounded
  nested-call records on the parent result — pi limits: 256 calls/8 KB per call/
  32 KB total/500-char errors). Codemode then becomes a consumer: embed a JS
  engine. Rust-native choices: `rquickjs` (QuickJS bindings) mirrors pi's exact
  semantics (interrupt flag, memory cap, deterministic `start()`); a WASM
  runtime is heavier. Supply-chain note: native dependency — justify per AGENTS
  dependency rules; the sandbox's only capability is injected tool calls, which
  now exist (B-5a). Tool-search can follow as a ranking layer over declarations.
- **Acceptance:** pi `packages/codemode` test corpus ported (source parser,
  `@options`, store caps, determinism/fingerprint replay); agent tests proving a
  nested call traverses before-hook + authorization and appears with
  `parentToolCallId`; negative controls: timeout kill, memory cap, unauthorized
  nested call denied. Gates: all six. Test impact: `add` (large).
- **Uncertainty:** engine choice (QuickJS vs WASM) needs a spike measuring
  interrupt-latency and binary size on Windows.

### B-6 Extension runtime parity (trade-off card — recommend targeted parity, not a rewrite)

- **Findings:** EXT-01..10, CLI-12.
- **Assessment:** opi's out-of-process adapters are a deliberate trust boundary
  (H-13) — do **not** replace with in-process TS-equivalent scripting. The parity
  gaps that matter to reproduction are observable surfaces, not the process model:
  event coverage (session lifecycle, message stream, provider request/response/
  stream hooks), extension state visibility (typed entries), UI context over RPC
  (dialogs/status/widgets — pairs with CLI-17's missing `extension_ui`
  subprotocol), flags/shortcuts registration, and provider registration beyond
  hardcoded OpenAI-completions overrides.
- **Approach:** extend the adapter protocol incrementally: event subscription
  whitelist → fuller event set; add `extension_ui_request/response` to the RPC
  schema; accept per-adapter declared flags surfaced in `--help`; let adapters
  declare wire API + model metadata instead of hardcoding.
- **Acceptance:** pi `docs/extensions.md` ordering guarantees re-expressed as
  adapter-protocol tests; an example adapter exercising each new surface; negative
  control: unknown flag still rejected when no adapter claims it. Gates:
  Behavior, Structure, Verification. Test impact: `add/update`.

### B-7 TUI engine gap (largest UX gap; scope decision required)

- **Findings:** TUI-ENGINE-01, TUI-MODE-02, TUI-ALTPORT-03, TUI-EDITOR-06,
  TUI-KEYS-04, TUI-KB-05, TUI-MD-08, TUI-IMG-09, TUI-THEME-10, TUI-UTIL-11,
  TUI-AUTO-12, TUI-LATEX-13, TUI-PROGSTAT-15, TUI-CLIP-16, TUI-MOUSE-17,
  CLI-13 (`/commands`).
- **Assessment:** full parity means building a rendering/input engine on top of
  ratatui (regular mode with scrollback integration, scroll state + search,
  mouse capture, Kitty negotiation, editor with cursor/undo/history/paste,
  OKLCH themes + OSC 10/11 scheme queries). That is a product-scale effort; a
  staged path: (1) scroll state + transcript search in fullscreen; (2) editor
  cursor/undo/history + bracketed paste; (3) keybinding vocabulary beyond 5 keys;
  (4) mouse; (5) regular mode (structural — ratatui alt-screen assumption);
  (6) themes/color + images. Each stage is independently shippable.
- **Acceptance:** per-stage interaction tests against a pty fixture (send keys,
  assert rendered frames); pi keybinding defaults parse and bind; negative
  control: unknown key sequence does not mutate editor state. Gates: Behavior,
  Delivery. Test impact: `add` per stage.

### B-8 Session/CLI surface parity

- **Findings:** CLI-02..06/09/12/19..23, SES-01..09.
- **Approach:** mostly additive flags/flows on existing machinery: `--continue`,
  `--session/--session-id/--session-dir`, `--no-session` (requires lazy creation —
  invert SES-06's eager `SessionWriter::create` into first-write creation),
  `--name`, `--models` cycling (needs model-cycling state in interactive),
  `--thinking`, `--exclude-tools` with pattern support, `--tui-mode`, `--offline`,
  `--approve/--no-approve` aliases, piped-stdin/TTY auto-print, `@file` inlining,
  extension-flag pass-through (clap `allow_unknown` pre-scan), `auth check/
  print-api-key/print-bearer-token`, first-run setup, startup migrations,
  `pi update`-style self-update. Session layout (per-cwd dirs, timestamp+uuidv7
  names, lazy create) and v3-format compatibility are policy decisions: either
  adopt pi layout/IDs (breaks opi v2 readers; needs migration) or record the
  difference permanently (H-14 already declares it).
- **Acceptance:** flag-by-flag golden help/behavior tests derived from pi's
  `args.ts` usage text; session round-trip tests for any layout change; negative
  controls: `--fork` conflict diagnostics, missing-session-cwd error paths.
  Gates: Behavior, Delivery. Test impact: `add/update`.
- **Note:** HTML export (SES-07) is a self-contained renderer task — vendored
  marked/highlight equivalents in Rust or a template approach; acceptance =
  snapshot-diff against pi's template output for a fixed session.

### B-9 Tool-contract parity

- **Findings:** RUN-TOOL-01..08, RUN-GUARD-01, RUN-QUE-01, RUN-COMP-01, RUN-USAGE-01.
- **Approach:** multi-edit `edit` schema (batch + per-edit uniqueness), `grep`
  parameter set, `find` limit, `ls` defaults, bash: raise timeout bound, spill
  oversized output to a file + `full_output_path`, interleave stdout/stderr at
  source; read: 50 KB cap (or document the difference), image mode via existing
  `image.rs` plumbing + output schema; powershell tool for Windows parity;
  stdout-takeover guard for JSON/RPC; file-mutation queue around concurrent
  mutations; compaction: model-generated summaries + file-activity carry-over +
  branch summaries (pi defaults reserve 16384/keep 20000); use catalog pricing in
  `SessionCoordinator::cost_summary` instead of the hardcoded table.
- **Acceptance:** per-tool schema/behavior tables from pi source pinned as
  fixtures (params, defaults, truncation metadata, error text); interleaving
  verified with a scheduled-output script; negative controls: non-unique edit
  rejection, limit-0 read, timeout kill leaves spill path. Gates: Behavior,
  Safety, Verification. Test impact: `add/update`.

### B-10 Diagnostics/telemetry parity (scoped)

- **Findings:** EXT-20..24, TEL-CTX-01..TEL-INMEM-05, AI-AUTH-10.
- **Approach:** decide scope: minimum viable parity = crash-log store + bug-report
  bundle (redaction machinery already exists in opi) + `PI_TIMING`-style startup
  profiling + cache-miss stats; telemetry library parity (span lifecycle,
  propagation, metrics, schema DSL, InMemory store, conformance kit) only if a
  second consumer appears — pi keeps it vendor-neutral by design; opi's tracing
  carrier may remain if cross-process correlation is never required (H-13
  non-goal). API-key interactive login (`/login` for env-key providers) is a
  small interactive_auth extension.
- **Acceptance:** crash/bug-report artifacts byte-stable under redaction tests;
  login stores a key without network. Test impact: `add`.

### B-11 chord/durable/env: record, don't chase (horizon card)

- **Findings:** CHD-01..10, DUR-01..13, ENV-01..08, H-01..H-05.
- **Assessment:** these are standalone library surfaces the pi product itself
  does not consume (CHD-10). Full reproduction would mean porting a 213K-LOC
  runtime stack with no product integration in the target snapshot. Recommend:
  treat as **design horizon only**; revisit if pi's product starts consuming
  durable (H-05 points that way). The one durable-class capability with product
  value today is commit-before-show + run-level resume (DUR-01/03/05) — opi's
  session stack would need a transactional commit unit and a replay policy to
  reach it; that is an architecture decision, not a port.
- **Acceptance (if ever pursued):** pi durable storage-conformance suite
  semantics re-expressed; crash-injection tests proving interrupted model
  requests count as failed attempts. Gates: all.

### B-12 Retain opi-only structures (no action, interference check)

- **Findings:** AGT-EVENT-02, AGT-ONLY-* (authority, evidence, validation,
  diagnostics, SDK, session stack), RUN-EXEC-01, PKG-06/07, EXT-26/27, ENV-07,
  EVL-05, TUI-OPI-19, AI-UTL-07/27.
- **Assessment:** none of these block pi reproduction except where they change
  accepted behavior already recorded `different` (event redaction hides args from
  public subscribers; transactional rollback discards failed-turn transcripts;
  authorization gate blocks un-authorized execution; keychain vs auth.json).
  Each is a visible parity difference by design; keep them explicit in any
  conformance matrix rather than silently diverging. B-cards above already
  treat them as intentional differences where relevant.

### Suggested verification order

B-1 (foundation, cheap) → B-2/B-3 (wire-level, small) → B-9/B-8 (tool+CLI surface,
mechanical) → B-4 (MCP, large but isolated) → B-5a nested calls → B-5b codemode →
B-6 (protocol extension) → B-7 (TUI stages) → B-10; B-11 parked at horizon.
Uncertainties: B-3 endpoint semantics, B-5 engine choice, B-7 stage-5 structural

migration.
