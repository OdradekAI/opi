### A.2 调用流追踪（产品核心：agent 会话）

```text
pi:      pi(cli.ts) -> modes -> AgentSession(core/agent-session.ts) -> Agent(agent.ts)
         -> runAgentLoop: prepareNextTurn -> prepareRequest(每一轮) -> streamFn
         -> partial 以 message 事件形式发出 -> executeToolCalls(before/after 钩子、
         onUpdate 进度、嵌套 runToolCall) -> finishTurn(可强制续轮选项)
         -> steering/follow-up 轮询(QueueMode) -> 失败 = 追加失败消息
         -> session-manager v3 JSONL（懒创建、按 cwd 分目录）

opi:     opi(cli.rs) -> runner/interactive/rpc -> harness.rs -> Agent::new(registry
         + authorizer) -> arm_run -> agent_loop: steering 全量排空 ->
         prepare_initial_turn(仅首轮) -> Models::prepare_call ->
         ChatStream 事件(仅 assistant 有 message 事件、delta 脱敏) ->
         preflight(resolve -> before 钩子 -> schema -> authorize) ->
         execute_authorized(未接进度回调) -> ToolExecutionEnd(源顺序)
         -> should_stop_after_turn(布尔；无法强制一轮) -> 队列轮询 ->
         prepare_next_turn_transaction(有担保时) -> 失败 = 回滚到已提交基线
         -> SessionCoordinator v2 JSONL（急切创建、扁平目录）
```

### A.3 最高影响差异（引用记录；细节见证据文件）

**模型/运行时层（维度 1,3,4）：**
- 目录数据：opi 内嵌了一份逐字节校验的 pi 发布工件，但锁定在 **pi-ai 1.3.0 修订版**
  （`manifest.json` `local_origin: .repo/pi-1.3.0`），而 pi 1.5.0 锁定 `f4dbabe…`
  （AI-MOD-07）；抽查显示已含 1.5.0 时代条目，完整差异离线不可证（AI-MOD-02）。产品
  `--list-models` 仅展示目录 42 个 provider 中的 **11 个**（`provider_factory.rs:517`；
  EXT-16）。
- `promptCache {short,long}` 生命周期存在于工件中，但**解码时被丢弃**（以两个布尔值替代；
  AI-MOD-03）。无 pi.dev 覆盖语义：无 ETag/304 再验证、无 4 小时窗口、无
  lastModified>generatedAt 门 — opi 的 HTTP 源是裸 GET；已存 etag 从不参与任何决策
  （AI-MOD-10）。Radius 网关动态拉取缺失（AI-MOD-11）。pi 刷新为并发 + 逐 provider 发布 +
  未知类型过滤；opi 顺序执行、单次末端提交、fail-closed（AI-MOD-09）。
- chat 重试集合更窄：pi 重试 408/**409**/429/5xx + `x-should-retry`；opi chat 准入仅重试
  类型化的 429/408/504（ProviderSide 不可重试），而 opi 的 typed-op 传输确实复现了完整阶梯
  （AI-STR-06）。agent 级消息文本分类器缺失（配额/计费/网关字符串；AI-STR-07；
  AI-UTL-26 模式列表漂移，含缺少边界环视）。
- 无默认 10 分钟请求超时（pi SDK 默认）— 除非调用方设置 `timeout`，opi 会一直挂起直到取消
  （AI-STR-09）。`durationMs` 仅在约 8 条 wire 中的 3 条上赋值（AI-STR-04）。事件 wire 标签
  不同（`toolcall_*`→`tool_call_*`、`toolUse`→`tool_use`），凡序列化事件处均可观察
  （AI-STR-01）。错误接缝：pi 带内 `error` 事件 vs opi 单个 `Err(CallFailure)`
  （AI-STR-02）；`partial` 共享活对象 vs 事件时点克隆（AI-STR-03）。无
  ClientIdentity/UA/归因框架；OpenRouter 头硬编码为 opi 自身身份（AI-STR-19、AI-UTL-20、
  AGT-IDENT-01）。
- 消息数据契约：opi 的规范 `ToolCall.arguments` 是**原始文本**（pi：解析后的对象），无
  `namespace`、无 `endTurn`、工具结果无 `usage/durationMs/nestedCalls`；opi 增加
  `not_executed`、`truncated`、`wire`、projection facts；Usage 不内嵌成本对象
  （AI-UTL-08..12）。

**TUI（维度 9）：** opi 把引擎委托给 ratatui+crossterm，只交付组件 — 无 regular（内联）
模式、无滚动回看/滚动状态、无会话内搜索、无鼠标、无 Kitty 按键/释放/重复（键绑定：5 个
键、3 个动作 vs 约 45 个）、无编辑器（仅追加/删除的输入行，无光标/撤销/历史/粘贴 — 协调者
已验证）、无自动补全、无 LaTeX、无 OSC 7501、无剪贴板，markdown 仅渲染标题/段落/代码围栏
（无列表/表格），主题是固定 RGB 映射（无 OKLCH/终端配色查询），图像仅环境探测 + PNG-kitty
且 Sixel 为存根（TUI-ENGINE-01..TUI-OPI-19）。

**schema/telemetry（维度 19,17）：** opi-ai 的 `schema` 是私有 TypeBox 方言引擎，不是
pi-schema 那种通用 JSON Schema 2020-12/7 库（无 draft 选择、无 builder DSL、无官方套件
一致性、首错脱敏 vs 全错、固定格式集、单文档 $ref）— 但工具参数强制转换管线仍是带两处
已披露分歧的忠实移植（SCM-*）。opi telemetry 是进程内 tracing 载体：无 span 生命周期、
无传播/链接、无指标、无 schema DSL、无 InMemory 存储/一致性套件（TEL-*）。产品诊断：
无 bug-report/上传、无 crash log、无安装遥测、无缓存未命中统计、无计时、无 git 分支页脚
（EXT-20..24）。

**chord/durable（维度 6,18）：** **缺失** — 无 host/contract/link/delta/热重载/principal
运行时（chord），无持久会话/任务/检查点/调度器/重放/子 agent/观察/存储后端（durable）；
opi 的"持久"表面是 transcript 级会话持久化（JSONL 追加 + 条目级崩溃恢复 + 单文件内分支
树），属于更弱的持久性类别：中断的运行会丢失、无提交后才展示、无任务状态机
（CHD-01..10、DUR-01..13）。值得注意的是，**pi 产品同样不消费 chord/durable/env**
（coding-agent 依赖不含它们；CHD-10）— 它们是快照中的独立库表面。

**env/evals/其他 package（维度 18,20）：** pi-env（SSH 远程执行守护进程 + fs/watch/pty
表面）无对应物；opi-sandbox 是另一种东西（本地 OS 限制；opi-only，ENV-01..08）。
pi-evals（vitest-evals 活模型行为评测 + docker 差异臂文档提升）vs opi-eval（冻结跨
agent 实验、密封 bundle、离线重判、确定性一致性）：两者都存在，设计不相交
（EVL-01..07）。
