## Reading and interpretation

Read scope, ownership and call states first. Follow AIR → decision/evidence → V in [acceptance-matrix](acceptance-matrix.md). Consult the retirement table before deleting a surface. [README](README.md) records checks actually run; acceptance cases below are future designs.

MUST is an obligation in a future admitted implementation of this selected candidate. SHOULD permits a documented exception preserving the stated behavior and verification. MAY is optional within scope. An explicit evidence blocker is not permission to guess a contract. Confirmation selects a target; it does not prove implementation or grant admission.

The old `opi-spec` placement/admission rationale is a potentially outdated reference, not a veto of established pi semantics here. Formal reconciliation must record the Rust implementation direction, multi-operation SDK, dynamic trusted revisions and actual per-call input provenance. Existing CONTEXT terms for User Policy, Package Trust and Capability Permission retain their meanings: model content cannot grant authority. Reconcile Runtime Input Binding's run-wide description with immutable initial provenance plus immutable per-call revisions; ordinary trusted updates do not require a child session. This candidate changes no formal document.

## Problem, goal and scope

Current opi chat selection can disagree with actual dispatch. Legal network chunking can corrupt UTF-8; prepared streams can expose events after terminal; producer cleanup differs by adapter. The request snapshot loses chronological system/tool changes. Tool images become placeholders. Compat settings with real pi behavior are present but disconnected. Full thinking continuation, SDK operations and published product paths need coherent owners and offline acceptance.

Implement pi's established observable semantics through Rust ownership, typed states and errors, bounded queues and explicit lifetimes. Preserve useful opi guarantees: known/unknown usage, secret-safe errors, frozen low-level authentication, mandatory final tool authorization and source-preserving legacy migration. Correct demonstrated defects rather than use pi's implementation accidents as an oracle. No TypeScript symbol/file compatibility, identical model output, cache savings, performance or billing accuracy is promised.

Selected scope:

- Existing chat binding, framing, terminal, cancellation and release correctness.
- Ordered transcript, named sections, tool add/remove/redefine, default native-or-collapse projection, trusted updates between calls, failure/result recovery and session migration.
- Effective compat, thinking effort selection, strict/grammar sampling and opaque continuation across existing adapter families.
- Shared typed image/classifier SDK operations: OpenRouter Chat-wire images; TypeSafe/OpenRouter System One choice/bool/ordered-score. SDK/embedded callers first; no default terminal operation tool.
- Product remote catalog/cache/refresh, SDK/product Codex auto WS/continuation/SSE fallback, optional tool_search connection and explicit high-level recovery.
- Public deferred submit/fetch/cancel lifecycle and a reopenable offline consumer fixture. This does not claim a verified built-in remote adapter.
- Explicit optional telemetry context across selected SDK operations, with host-owned backend and domain instrumentation; no automatic SDK call/attempt schema or exporter.

Out of this candidate: full MCP/codemode product port, remaining published image/classifier adapters, dedicated OpenRouter Image API, image streaming, real remote deferred adapter without protocol evidence, experimental virtual classification routing, complete unadopted Responses Lite, a generic operation/plugin/transport framework and billing-policy redesign. These are identified coverage gaps or experiments, not rejected because opi lacks consumers. Reassessment triggers are in the final section.

## Actors and scenarios

1. An embedder selects a model and observes that same executable binding in preflight and dispatch.
2. A stream consumer observes one terminal outcome and releases an abandoned attempt.
3. A trusted host changes instructions or tool definitions between calls without changing a pending call's revision.
4. A session user migrates, resumes, forks and compacts without invented history or sibling contamination.
5. A tool host sees raw, normalized and executed arguments, and authorizes the actual execution.
6. An SDK caller customizes a request within binding constraints and receives owned typed media/answers with truthful accounting.
7. A product user starts with cached models, updates them after startup, and can choose offline or SSE operation.
8. A continuing Codex caller uses cached context only when equivalent full input exists.
9. A caller observes distinct recovery attempts, or resumes a deferred check without resubmitting work.
10. An embedder passes its existing tracing parent through all SDK call modes without replacing its subscriber or serializing backend objects.

## Responsibilities and owned state

| Owner | Responsibility | Boundary |
|---|---|---|
| opi-ai catalog/collection | Operation-qualified records, atomic revisions, unique preparation, frozen call and attempt lease | Listing is not executability; no implicit provider/account fallback |
| opi-ai adapters/runtime | Effective compat, wire compilation/parsing, owned transport/cache, continuation | No second model selection or local tool execution |
| opi-ai transcript/validation | Chronology, normalization, projection, schema conversion | Request views do not rewrite canonical facts or authorize tools |
| SDK auth/resolver | Injectable API/OAuth/AWS sources, secret values, source failure and expiry | Product config/permissions choose use; no import-time discovery |
| opi-agent | Immutable call/batch execution revision, trusted updates, hooks, final authorization | Registered, active-callable, wire-visible and authorized are distinct |
| Session/product transaction owner | One branch, input acceptance, checkpoint, migration and durable acknowledgement | No parallel context writer; no fabricated old material |
| Reference Product model/session owner | Remote source/cache, refresh coordination, transport/recovery defaults, tool_search activation | Bare SDK does not contact pi.dev by merely being constructed |
| SDK operation/caller | Typed image/classifier/deferred methods; caller owns saving, thresholds and poll schedule | No tool authority, automatic file writes or hidden polling framework |
| opi-ai telemetry module / Agent or SDK host / host backend | Explicit context mechanism / domain vocabulary and status / subscriber, export, sampling and flush | No automatic SDK spans, global initialization, durable-state replacement or implicit upload |

A logical call owns one final request/model/auth binding; an attempt executes that binding. At most one executable attempt is active per logical call. A high-level recovery group relates new logical calls within the same run/turn and intent; it does not mutate an old call's credentials or splice fresh output into an old stream. Closed tasks may finish non-executable cleanup while the next attempt begins; cleanup must eventually release local resources.

Preparation selects immutable model identity/revision and explicit input data before auth. Auth may lawfully supply endpoint/header material. Endpoint-dependent compat defaults are resolved using the final endpoint, then one final binding is validated and frozen before transport. This completion step never reselects a model. SDK transforms run once before payload freeze. Changes appear in effective projection/provenance; execution authority remains the trusted call revision.

A trusted context/loadout update is assembled and validated off to the side, committed by the existing single transaction owner, then atomically installed at a call boundary. A model response and its tool batch retain that call's execution revision. Current User Policy can still revoke permission. Durable input acknowledgement survives later auth/network failure or cancellation; pre-ack failure preserves old state and queued input. For explicitly durable session callers only: after final binding and payload freeze, the same transaction owner MUST durably acknowledge the accepted prefix, trusted revision and actual projection before the first transport dispatch. Reuse suitable existing events/records; no fixed pair of extra appends per call is prescribed. Failure or cancellation before this acknowledgement prohibits dispatch while preserving already accepted input. Commit/cancel races follow the existing acknowledgement rule: an acknowledged fact remains durable, and observed cancellation still prevents subsequent dispatch. Persist no secrets; an unobserved/crashed dispatch is not recorded as successful.

Sessionless SDK callers use owned memory and the same model/message/wire validation without session files, children or Promotion. No transaction owner, Agent authorizer, product config or storage acknowledgement is required; AIR-015–019 govern durable integrations only. Generation does not append caller Context, execute tools, start product recovery or background refresh. Execution authorization in AIR-024/041 governs tool-executing hosts/Agents, not a library chat prerequisite.

### Plain-JSON normalization and sampling

Rust's public schema is JSON; no TypeBox private marker selects a second coercion algorithm. Preserve raw JSON/string and parsed status, clone before normalization, and record effective execution separately. Existing exact Rust integer values need not acquire JavaScript parse-time precision loss; record that representation difference in differential fixtures. Primitive coercion from strings uses finite ECMAScript binary64 Number/String semantics, with raw preserved; it is not lossless conversion of arbitrary precision strings.

| Rule | Fixed behavior and mechanical corpus |
|---|---|
| Optional null | Delete an existing optional property null only when its independent original subschema rejects null and has no string $ref; otherwise keep. Recurse properties/items, not universal union/ref resolution. Test required, nullable, ref, nested and extra null. |
| Number/integer | null→0, bool→0/1; nonblank numeric strings accept ECMAScript numeric syntax, finite only, integer only if integral. Invalid conversion leaves original for full validation. Include sign/exponent/hex/binary/octal, whitespace, Infinity/NaN, overflow and2^53 boundaries. |
| Boolean | null→false, exact strings true/false and numeric1/0 only. Strings TRUE/1/0 and numeric2 remain invalid for boolean. |
| String/null | null→empty string; number/bool use ECMAScript String, not Debug or object serialization. Null target converts only empty string,0,false. Include −0,1e21,1e−7, arrays and objects. |
| Type arrays/unions | Preserve already allowed JSON type. Otherwise try ordered primitive conversions. allOf sequential, then anyOf, then oneOf; unions first preserve any already-valid full arm, otherwise clone per arm and choose first validating converted arm. Whole-schema final validation still enforces oneOf uniqueness. |
| Objects/arrays | Transform existing properties/schema-valued additionalProperties/items/tuple positions only. No defaults, removal of forbidden extras, scalar-array wrapping or string-object parsing. |
| Final check | Fully validate original trusted schema, including root/enum/constraints; invalid root cannot escape by returning raw as validated. Failure is typed/redacted and zero execution. Hook can mutate only after this stage; final authorization uses the actual value. |

Strict wire conversion requires object root; recursively make all properties required and formerly optional nonnullable fields nullable, set additionalProperties=false, leaving trusted schema unchanged.
