## Findings

### P17-AUD-001: After-call presentation replacement rewrites terminal evidence outcome

- Axis: runtime-fidelity
- Severity: Major
- Conformance effect: blocks
- Requirement IDs: P17-OUT-004
- Claim: `ExecutedTool::ordinary` receives the hook replacement and derives `ToolExecutionOutcome` from its `is_error`, so the finalized evidence can silently report the opposite of the real tool result.
- Evidence: `agent_loop.rs:1964-1997` replaces the real result; `agent_loop.rs:1578-1583` derives the outcome; `agent_loop.rs:1682-1687` emits it.
- Refutation attempted: current callers and alternate terminal-error paths were inspected; typed `ToolError` paths retain actual outcomes, but every ordinary `Ok(ToolResult)` replacement uses this conflated path. The current Phase 17 replacement test checks later authorization fields only and does not inspect evidence.
- Suggested closure: retain the actual execution outcome before the hook and use the replacement only for provider/public presentation; add a discriminating success-to-error and error-to-success evidence test.

### P17-AUD-002: Current audit head has no three-platform acceptance result

- Axis: test-quality
- Severity: Major
- Conformance effect: blocks
- Requirement IDs: P17-PLT-001, P17-A15
- Claim: platform-neutral passage cannot be established for the exact current baseline.
- Evidence: the workflow defines the matrix, but `gh run list` returned no run and the checks API could not find the exact local commit; focused execution covered Windows only.
- Refutation attempted: the Phase ledger historical CI identity was checked as metadata, but extensive Phase 17 runtime/test changes exist after that SHA, so it cannot establish the current baseline.
- Suggested closure: publish the exact remediation head and obtain a green Phase 17 acceptance matrix on Linux, macOS, and Windows.
